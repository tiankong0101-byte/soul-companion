## 1. 为什么需要长期记忆？

Open-LLM-VTuber 通过 ChromaDB 等向量库实现长期记忆，让虚拟伴侣能"记住"用户。soul-companion v3.1 把这种能力引入到 Markdown 技能中：

- **跨会话连续性**：下次开新对话，菲菲能想起你上次说的
- **个性化**：记住生日、爱好、关系、关键事件
- **情感连接**：知道用户正在经历什么（离婚/升职/失恋）
- **降低成本**：避免重复询问基本信息

## 3. 数据模型

### 3.1 facts（结构化事实）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增 |
| category | TEXT | personal / preference / relationship / event / health / work |
| key | TEXT | 字段名（如 birthday, favorite_food） |
| value | TEXT | 字段值 |
| confidence | REAL | 0-1，1.0=用户明确说，<1=推断 |
| source | TEXT | user_explicit / inferred / imported |
| importance | REAL | 0-1，越高越不容易被遗忘 |
| created_at | TEXT | 创建时间 |
| updated_at | TEXT | 更新时间（trigger 自动维护）|

**UNIQUE(category, key)**：同 category+key 会 upsert（importance 取 max）

### 3.2 episodes（情景记忆）

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增 |
| session_id | TEXT | 会话 ID（同话题聚合） |
| role | TEXT | user / assistant / system |
| content | TEXT | 完整内容 |
| emotion | TEXT | sad / anxious / excited / angry / grateful / lonely / neutral |
| importance | REAL | 0-1（自动评估） |
| embedding_id | INTEGER | FAISS 索引里的 ID |
| tags | TEXT (JSON) | 标签数组 |
| created_at | TEXT | 创建时间 |
| last_accessed | TEXT | 最近一次被检索时间 |
| access_count | INTEGER | 累计被检索次数（热度） |

## 4. Embedding 策略

### 4.1 三种后端对比

| 后端 | 依赖 | 质量 | 成本 | 隐私 |
|------|------|------|------|------|
| **Ollama** | ollama + nomic-embed-text | ⭐⭐⭐⭐ | 免费 | ✅ 本地 |
| **OpenAI 兼容** | openai 包 | ⭐⭐⭐⭐⭐ | $0.02/M tokens | ❌ 上传 |
| **Hash 降级** | 无 | ⭐ | 免费 | ✅ 本地 |

**推荐**：本地起 Ollama + `nomic-embed-text`：

```bash
# 安装 ollama: https://ollama.com
ollama pull nomic-embed-text
ollama serve   # 默认 :11434
```

### 4.2 维度

| 后端 | dim |
|------|-----|
| nomic-embed-text | 768 |
| text-embedding-3-small | 1536 |
| bge-large-zh | 1024 |
| Hash | 768（可配）|

**注意**：换后端需要重建索引（删除 `data/memory.db` 重新导入）。

## 5. importance 启发式

```python
def estimate_importance(content, emotion):
    score = 0.5
    # 情绪加成
    score += {"sad": 0.3, "anxious": 0.3, "angry": 0.3,
              "lonely": 0.3, "excited": 0.2, "grateful": 0.2}.get(emotion, 0)
    # 关键词加成
    if any(k in content for k in ["生日", "去世", "分手", "结婚", "癌症", "我想", "我希望"]):
        score += 0.15
    # 长度加成
    if len(content) > 200:
        score += 0.1
    return min(score, 1.0)
```

**调参建议**：
- 想严格保留 → 把 `cleanup.importance_below` 设为 0.5
- 想激进遗忘 → 设为 0.2
- 想永久保留关键事实 → fact 用 0.9 即可（永远不会低 importance）

## 6. 与 LLM 集成

### 6.1 完整 RAG 流水线

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path("scripts").resolve()))

from llm_router import LLMRouter
from memory import MemoryStore, MemoryRetriever
from memory.embedder import create_embedder

# === 初始化（程序启动时执行一次）===
router = LLMRouter.from_config("config/llm.yaml")
store = MemoryStore("data/memory.db", create_embedder(backend="auto"))
retriever = MemoryRetriever(store)

# === 每轮对话 ===
user_input = "今天妈又不理解我了"

# 1) 检索相关记忆
ctx = retriever.build_context(
    user_input,
    include_facts=True,        # 注入事实
    include_episodes=True,     # 注入相关对话
    top_k_episodes=3,
    max_facts=15,
)

# 2) 拼到 system
system = f"""你是菲菲。

{ctx}
"""

# 3) 调用 LLM
resp = router.chat(
    messages=[{"role": "user", "content": user_input}],
    system=system,
    backend="anthropic",
)
print(resp.text)

# 4) 把这轮存进记忆
store.add_episode("user", user_input, emotion="sad")
store.add_episode("assistant", resp.text)
```

## 7. 自动遗忘

```bash
# 手动清理
python scripts/memory/cli.py cleanup
# 等价于：
python scripts/memory/cli.py cleanup --days 90 --threshold 0.3
```

**SQL 实现**：

```sql
DELETE FROM episodes
WHERE importance < 0.3
  AND (last_accessed IS NULL
       OR julianday('now') - julianday(last_accessed) > 90)
  AND julianday('now') - julianday(created_at) > 90;
```

**自动调度**（可选，cron / Task Scheduler）：

```python
# 每周日凌晨跑一次
import schedule
schedule.every().sunday.at("03:00").do(store.cleanup)
```

## 8. 性能与成本

### 8.1 存储

- SQLite：~1KB/fact, ~5KB/episode（含 embedding BLOB）
- 1 万条 episode ≈ 50MB（含 FAISS）

### 8.2 检索延迟

| 数量 | FAISS | numpy |
|------|-------|-------|
| 1K episodes | < 5ms | ~10ms |
| 10K episodes | < 20ms | ~100ms |
| 100K episodes | ~50ms | ~1s |

**建议**：超过 10K episode 切换到 faiss-cpu；超过 100K 用 IVF 索引。

### 8.3 Embedding 成本

- Ollama 本地：免费
- OpenAI text-embedding-3-small：$0.02 / M tokens
- 1 万条 episode（平均 50 字 ≈ 1.5M tokens）≈ $0.03 一次性

## 9. 故障排查

| 现象 | 原因 | 解决 |
|------|------|------|
| `Embedding 失败，使用 hash 降级` | Ollama 未启动 / OpenAI key 错 | 检查 `ollama serve` / env var |
| `hash embedder 检索质量差` | 正常，hash 不是真语义 | 启动 Ollama 或换 OpenAI |
| 检索返回空 | 索引为空 / 相似度阈值过高 | `python cli.py stats` 确认数据；降低 `min_similarity` |
| SQLite 锁错误 | 多进程访问 | 用单进程，或加锁 |
| `pickle.loads 失败` | 跨版本 Python | 删除 `data/memory.db` 重建 |
