# 📘 v3.0 多 LLM 后端路由 详细文档

> 适用版本：soul-companion v3.0.0+
> 最后更新：2026-06-16

## 1. 为什么需要多 LLM 后端？

Open-LLM-VTuber 支持 12+ LLM 后端，给用户选择权。soul-companion v3.0 把这种灵活性引入到 Markdown 技能中，让「菲菲」能：

- **按场景切换模型**：长文用 Kimi（128K），日常用 Claude Haiku，本地用 Ollama
- **降本增效**：把高消耗任务分流到便宜模型
- **隐私优先**：敏感话题用本地 Ollama，数据不出机器
- **多模态扩展**：未来加视觉模型只需实现一个 client

## 2. 架构

```
┌─────────────────────────────────────────────┐
│  Agent / OpenClaw                           │
│  检测触发词 → 决定 backend → 调用 router     │
└─────────────────┬───────────────────────────┘
                  │
                  ▼
┌─────────────────────────────────────────────┐
│  LLMRouter.from_config("config/llm.yaml")   │
│  - 加载 YAML                                │
│  - ${ENV_VAR} → os.environ                  │
│  - 选择 default_backend / 指定 backend      │
│  - 注入 feifei_persona.system_prompt       │
└─────────────────┬───────────────────────────┘
                  │
       ┌──────────┼──────────┬──────────┐
       ▼          ▼          ▼          ▼
   Anthropic   OpenAI    OpenAI兼容  Gemini   Ollama
   (Claude)    (GPT)     (DS/Zhipu)  (Google) (本地)
```

## 3. 配置文件详解

`config/llm.yaml` 顶层结构：

```yaml
version: "3.0"                    # 配置文件 schema 版本
default_backend: "anthropic"       # 不指定 backend 时用这个

defaults:                          # 全局默认值
  max_tokens: 4096
  temperature: 0.7
  top_p: 0.95
  timeout: 60
  retry: 3
  stream: false

backends:                          # 后端清单（可任意增删）
  anthropic:
    type: "anthropic"              # 必填：决定用哪个 Client 类
    api_key: "${ANTHROPIC_API_KEY}"# 必填：env 占位符或明文
    model: "claude-3-5-sonnet-20241022"
    max_tokens: 4096               # 可选：覆盖 defaults
    temperature: 0.7

feifei_persona:                    # 菲菲人设
  system_prompt: "..."
  mode_overrides:
    comfort: "陪伴模式"
    listener: "树洞模式"
```

### 3.1 后端类型 (type)

| type | 协议 | 适用 | base_url 备注 |
|------|------|------|---------------|
| `anthropic` | Anthropic Messages | Claude 全系列 | 默认 `https://api.anthropic.com`，可改代理 |
| `openai` | OpenAI Chat Completions | GPT-4o/4o-mini/o1 | 默认 `https://api.openai.com/v1` |
| `openai_compat` | OpenAI Chat Completions | DeepSeek/Zhipu/Moonshot/vLLM/Ollama-OpenAI 模式 | **必须**指定 `base_url` |
| `gemini` | Google generative | Gemini 1.5 Pro/Flash | 默认 `https://generativelanguage.googleapis.com/v1beta/models` |
| `ollama` | Ollama `/api/chat` | 本地 Ollama | 默认 `http://localhost:11434` |

## 4. Python API

### 4.1 基础用法

```python
import sys
from pathlib import Path
sys.path.insert(0, str(Path("scripts").resolve()))

from llm_router import LLMRouter

rt = LLMRouter.from_config("config/llm.yaml")

# 简单调用
resp = rt.chat(
    messages=[{"role": "user", "content": "今天有点累"}],
)
print(resp.text)
print(f"用时 {resp.latency_ms}ms, model={resp.model}")
```

### 4.2 指定后端 + 模式

```python
resp = rt.chat(
    messages=[
        {"role": "user", "content": "我妈又不理解我了"},
    ],
    backend="anthropic",      # 强制用 Claude
    mode="comfort",            # 用陪伴模式人设
)
```

### 4.3 流式输出

```python
for chunk in rt.stream_chat(
    messages=[{"role": "user", "content": "给我讲个睡前故事"}],
    backend="deepseek",
):
    print(chunk, end="", flush=True)
```

### 4.4 多轮对话（手动管理 history）

```python
history = [
    {"role": "system", "content": "你是菲菲。"},
    {"role": "user", "content": "你好"},
    {"role": "assistant", "content": "天哥，今天怎么样？"},
    {"role": "user", "content": "有点累"},
]
resp = rt.chat(history, backend="anthropic")
history.append({"role": "assistant", "content": resp.text})
```

### 4.5 Agent 集成示例（OpenClaw）

在 SKILL.md 中可加：

```yaml
llm_routing:
  default: anthropic
  rules:
    - if_user_says: "用本地"
      backend: ollama-qwen
    - if_user_says: "用 DeepSeek"
      backend: deepseek
    - if_context_tokens: ">30000"
      backend: moonshot
    - if_topic: "code"
      backend: deepseek
```

Agent 看到这些规则后，先匹配 → 再调 `rt.chat(..., backend=匹配结果)`。

## 6. 错误处理

| 异常 | 触发条件 | 处理建议 |
|------|---------|---------|
| `LLMError("未知后端类型: xxx")` | type 字段拼写错 | 检查 YAML 拼写 |
| `LLMError("缺少 xxx api_key")` | env var 未设置 | `export XXX_API_KEY=...` |
| `LLMError("Anthropic HTTP 401")` | key 无效或欠费 | 检查 key、账户余额 |
| `LLMError("Anthropic HTTP 429")` | 限流 | 降低频率或换后端 |
| `LLMError("重试 3 次仍失败")` | 网络问题 / 服务宕机 | 检查网络、看后端 status page |

默认 `retry: 3` + 指数退避（2^attempt 秒：2s, 4s, 8s）。**总计最多等待 14s**。

## 7. 性能与成本建议

| 场景 | 推荐后端 | 理由 |
|------|---------|------|
| 日常闲聊 | `anthropic-haiku` 或 `gpt-4o-mini` | 快 + 便宜 |
| 长文（>10K tokens）| `moonshot`（Kimi 128K）| 唯一支持 128K |
| 复杂推理 | `anthropic`（Sonnet 4.5）或 `o1` | 推理强 |
| 编程 | `deepseek`（V3）| 国产性价比之王 |
| 中文情感 | `zhipu`（GLM-4-Plus）| 中文微调 |
| 隐私敏感 | `ollama-qwen`（本地）| 数据不出机器 |
| 多模态 | `gemini-1.5-pro`（支持图片）| 唯一原生多模态 |
| Function calling | `anthropic` / `openai` / `deepseek` | v3.3 工具框架会用到 |

## 10. 常见问题

**Q: 调用时返回 `LLMError: 缺少 api_key`**
A: 检查 `echo $ANTHROPIC_API_KEY`（Linux/macOS）或 `echo %ANTHROPIC_API_KEY%`（Windows cmd）/ `$env:ANTHROPIC_API_KEY`（PowerShell）是否设置。

**Q: 流式响应看不到输出**
A: 流式响应使用 `iter_lines`，需要后端真的支持 SSE。Anthropic/OpenAI/Ollama 都支持，Gemini 需要 `&alt=sse` 参数（v3.0 暂未实现，需要的话告诉我）。

**Q: 如何在 Agent 中自动选择后端？**
A: 解析用户消息中的关键词（如"用DeepSeek"），提取 backend 名，调用 `rt.chat(..., backend=提取结果)`。详见第 4.5 节。

**Q: v3.0 和 v2.2 的 TTS 冲突吗？**
A: 不冲突。v2.2 的 TTS 是「把文字转语音」，v3.0 的 LLM 是「生成回复文字」，两者是流水线上下游关系：

```
用户语音 → [ASR v3.2] → 文本 → [LLM v3.0] → 回复文本 → [TTS v2.2] → 语音播放
```

v3.2 上线后端到端串联起来。
